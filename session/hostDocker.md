- `docker` here is the Docker of the machine Woodshed runs on, not this container's own: use it for the repo's compose services, Supabase local or Testcontainers.
  - Containers you start run on the person's machine beside this one, and keep running after this session ends unless you stop them. Stop what you started before you finish, unless it is still in use.
  - A bind mount such as `-v /work/...:/data` names a folder on the machine, not in this container: use named volumes.
  - A port a container publishes is the machine's. It is forwarded to the same port on 127.0.0.1 here within seconds (`/tmp/woodshed-docker-ports.log`), unless something here already listens on it, and `host.docker.internal:<port>` reaches it too.
  - Other sessions use the same Docker. Before you start a stack they may also start, give it a name of its own with this session's id, `{{SESSION_ID}}`: a compose project name (`docker compose -p <name>`), or Supabase's `project_id` in `supabase/config.toml`. Two stacks cannot publish the same port on the machine either: when `docker ps` shows another stack on the ports yours wants, give yours other ports too (Supabase's `[api]`, `[db]`, `[studio]` and the rest in `config.toml`).
